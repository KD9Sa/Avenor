# API contract (v1)

All routes begin `/api`; JSON uses camelCase, ISO UTC dates, string enums. API serves the real database in both providers. Frontend proxies `/api` to port 5080; Vite/Angular runs at 4200. Cookie credentials are same-origin. GET `/auth/csrf` returns `{ token }` and sets readable `XSRF-TOKEN`; Angular sends `X-XSRF-TOKEN` on every mutation. GET `/auth/me` returns UserDto or 401. POST `/auth/login` `{ organizationSlug, email, password }` returns UserDto, POST `/auth/logout` ends session. Demo: organization `northstar`, `alex@northstar.demo` (Admin), `jordan@northstar.demo` (Agent), `morgan@acme.demo` (Customer); password `AvenorDemo!2026` only when SeedDemo=true. Second tenant `meridian`, admin `admin@meridian.demo`, same explicitly seeded demo password.

UserDto: `{ id, name, email, role: 'Admin'|'Agent'|'Customer', tenantId, organizationName, organizationSlug, isActive, avatarColor? }`. List users via GET `/users` (staff only). POST `/users` `{ name,email,role,password }`; PATCH `/users/{id}` `{name?,role?,isActive?}` (admin only). GET `/customers` returns `{ id,name,email,company,ticketCount,openTicketCount }[]` scoped to tenant (staff only).

TicketDto: `{ id, number: number, subject, description, status: 'Open'|'InProgress'|'Pending'|'Resolved'|'Closed', priority: 'Low'|'Normal'|'High'|'Urgent', category, channel: 'Email'|'Portal'|'Chat', customerId, customerName, customerEmail, assigneeId: string|null, assigneeName: string|null, createdAt, updatedAt, responseDueAt, resolutionDueAt, firstRespondedAt: string|null, resolvedAt: string|null, isEscalated, version: number, tags: string[] }`.

GET `/tickets?search=&status=&priority=&assigneeId=&page=1&pageSize=10&sort=updatedAt&direction=desc` returns `{ items: TicketDto[], total, page, pageSize }`. Optional filters may be absent; `assigneeId=unassigned` means no assignee; `assigneeId=me` current user. Sorting whitelist: createdAt, updatedAt, priority, subject, number. GET `/tickets/{id}` returns `{ ticket: TicketDto, messages: MessageDto[], history: AuditDto[] }`.

POST `/tickets` `{ subject,description,priority,category,customerId?,channel?,tags? }` returns TicketDto. Customers always own created tickets. Staff must supply an existing customerId. PATCH `/tickets/{id}` `{ version, status?,priority?,assigneeId?,tags? }` returns TicketDto; only staff can patch, assigneeId null unassigns. Stale versions return 409. POST `/tickets/{id}/messages` `{ body,isInternal:false,version }` returns detail `{ ticket,messages,history }`; customers cannot post internal notes. Staff reply records first response, customer reply reopens Resolved. MessageDto `{id,body,isInternal,authorId,authorName,authorRole,createdAt}`.

GET `/dashboard?days=7` (staff): `{ totalTickets,openTickets,resolvedTickets,pendingTickets,unassignedTickets,overdueTickets,slaCompliance,averageResponseMinutes,volume: [{date,created,resolved}],byStatus:[{status,count}],byCategory:[{category,count}],team:[{id,name,role,activeTickets,resolvedTickets}],recentTickets: TicketDto[] }`. Days 7, 30, 90; metrics are scoped to created-in-period tickets (except team active counts and current queue/overdue). GET `/reports/export?days=30` produces CSV (staff only).

GET `/settings` returns `{ organizationName,organizationSlug,assignmentStrategy:'Manual'|'LeastBusy'|'RoundRobin',slaPolicies:[{priority,responseMinutes,resolutionMinutes}],businessHours }`; PUT same shape updates (admin only). Sla priorities exactly Low,Normal,High,Urgent; positive durations <= 43200; existing deadlines retain their original policy.

GET `/audit?page=1&pageSize=20` returns `{ items: AuditDto[],total,page,pageSize }` (admin). AuditDto `{id,action,description,actorName,createdAt,ticketId:string|null}`. GET `/notifications` returns NotificationDto[] `{id,title,body,ticketId:string|null,isRead,createdAt}`; POST `/notifications/read` `{ids:string[]}` marks permitted notifications read. GET `/events` streams SSE invalidation messages named `update`; frontend refreshes active data after notifications. GET `/health` is anonymous health readiness.

Errors: RFC ProblemDetails `{ title,status,detail,errors? }`; 400 validation, 401 session, 403 permission, 404 scoped resource, 409 concurrency/state, 429 login limit. Success: 200/201/204. IDs GUID strings. Empty results are arrays. Do not expose stack traces or password hashes. Report exports are capped at 10,000 records; SLA/chart periods use UTC dates and elapsed minutes. SSE delivery is in-process for one API instance. Offline non-demo organization provisioning is documented in BOOTSTRAP.md.
